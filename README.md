# PoE1 自动工艺

Python 桌面工具：通过 **Ctrl+C 剪贴板** 读取简体中文装备词缀，用 **OpenCV 模板匹配** 执行园艺台单工艺或多步骤通货流程。

> 警告：自动化可能违反《流放之路》用户协议，存在封号等风险，请自行承担。本项目仅供学习交流。

## 功能

- 解析中文客户端物品文本（稀有度、名称、词缀、数值）
- 目标规则：文本包含 + 可选数值比较（`>= > <= < =`），支持 ALL / ANY
- 工艺模式：
  - **通用**：重复点击你已在游戏内选中的工艺
  - **预设**：先点选模板对应工艺，再执行
  - **多步骤**：按配置右键通货、左键目标装备，并根据每步结果分支
- 多步骤流程支持：
  - 每步独立配置通货模板、动作后稀有度和词缀规则
  - 命中/未命中分别选择：下一步、重复、跳转、完成或停止
  - 可拖成循环，例如“改造命中 → 富豪检查 → 失败重铸 → 回到蜕变”
- 安全停止：F8 热键、最大次数、连续解析失败、模板找不到、生命力不足模板、词缀连续无变化
- CustomTkinter GUI

## 环境

- Windows（依赖 `pywin32` 找窗口 / 前台）
- [uv](https://github.com/astral-sh/uv) + Python 3.11+ 推荐
- 游戏建议：**窗口 / 无边框窗口**，不要用互斥全屏
- 部分环境模拟键鼠或全局热键需要**以管理员身份**运行

```powershell
cd e:\projects\poe_crafting

uv run python main.py
```

测试：


（仍保留 `requirements.txt`，也可用 `uv pip install -r requirements.txt`。）

## 自定义匹配图片

将 PNG 放到 `assets/templates/`，**推荐直接在 GUI 粘贴**：

1. 游戏内用 `Win+Shift+S`（或任意截图工具）截取按钮/物品槽  
2. 回到本工具窗口，在「模板配置」区选择保存目标（如 `craft_button`）  
3. 按 **Ctrl+V** 或点「从剪贴板粘贴」→「保存到模板」  
4. 右侧列表会显示是否已保存；也可用「打开模板目录」手动管理文件  

| 文件 | 说明 |
|------|------|
| `craft_button.png` | **必需** 执行工艺按钮 |
| `item_slot.png` | **必需** 目标装备本身（工艺槽或背包内，悬停后 Ctrl+C） |
| `reforge.png` 等 | 预设模式：对应工艺条目（须在可见区域） |
| `not_enough_lifeforce.png` | 可选：生命力/材料不足提示 |

多步骤模式使用的常用通货图标已根据 [PoE 官方静态数据](https://www.pathofexile.com/api/trade/data/static) 内置，包括蜕变石、改造石、增幅石、富豪石、重铸石、崇高石和剥离石；无需自行截图。

截取建议：

1. 游戏 UI 缩放固定，分辨率与日常游玩一致  
2. 只截按钮核心文字/图标，不要过大背景  
3. 在 GUI 调「模板阈值」并用「测试模板匹配」验证 score  

> 规则输入框内的 Ctrl+V 仍用于粘贴文字；焦点在输入框外时 Ctrl+V 会粘贴图片。

## 使用步骤

1. 启动游戏与本工具  
2. 放入园艺台物品，截好模板并测试匹配  
3. 配置目标规则（例：包含 `最大生命`，算子 `>=`，阈值 `80`）  
4. 选择通用或预设模式；通用模式请先在游戏内点好工艺  
5. 点「确认并开始」；紧急停止默认 **F8**  
6. 「刷新装备」可单次读取槽内物品；「解析当前剪贴板」可在游戏里手动 Ctrl+C 后调试解析  

## 多步骤通货流程

1. 到「多步骤」页添加、删除或排序步骤。
2. 每步从中文列表选择“使用通货”，再选择动作后应有的稀有度并配置词缀条件。
3. 分别设置“命中后”和“未命中后”的去向。跳转使用稳定的步骤 ID，步骤改名或排序不会破坏跳转。
4. 到「模板」页只需保存目标装备位置 `item_slot`；常用通货图标已经内置。
5. 直接点击「多步骤」页右上角的“开始流程”；程序会自动切换到多步骤模式。

启动后的第一个动作始终是：只将鼠标移动到目标装备上并按 `Ctrl+C`，不发送鼠标点击。读取成功后会先根据当前稀有度和词缀恢复流程状态，再使用通货。解析器兼容国服的 `稀 有 度: 魔法` 格式；真正不带稀有度但有物品等级的装备才按普通处理。高级词缀说明行、圣战者/督军标记和出售绑定信息都不会计入显式词缀数。首个通货按当前窗口做多尺度初搜；核对成功后，后续通货会根据本次画面的实测尺寸使用 SIFT 局部特征聚类定位，失败才回退到同尺度/宽尺度彩色匹配。窗口尺寸变化时会重新标定，不绑定固定分辨率。每个候选在右键前还必须通过 `Ctrl+C` 复制出对应的中文通货名。名称不符、未复制成功或候选落在装备区域内时，都会在点击前停止。

仓库内置的 `config/workflow.json` 示例为：

1. 蜕变后检查“元素伤害提高 ≥ 19”或“最大生命 ≥ 130”；任意一条达到 T1 就保留，否则进入改造。
2. 改造反复洗，直到先得到上述任意一条 T1 目标，元素和生命两种起手完全对称。
3. 当前魔法装备恰好只有 1 条显式词缀时使用增幅石，尝试补出另一条；已有 2 条则不消耗增幅石，直接进入富豪。
4. 无论增幅是否命中都再使用富豪石；富豪后必须同时具备“T1 元素伤害”和“T1 最大生命”才完成。
5. 富豪仍未补齐则重铸为普通，并跳回第 1 步。

动作后的剪贴板读取若暂时失败，程序只会重读装备，不会重复施放当前通货。

## 配置

- `config/settings.json` — 延迟、次数、热键、窗口标题关键字、阈值等  
- `config/rules.json` — 目标规则  
- `config/workflow.json` — 多步骤通货流程

## 限制

- 仅简体中文物品文本
- 数值规则默认取词缀行**第一个**数字
- 预设工艺需目标在可见列表中（不自动滚动）
- 多步骤模式要求目标装备及所有会用到的通货模板在当前画面可见
- 不读内存、不注入进程
