# POE Tools

Electron 桌面工具：通过 **Ctrl+C 剪贴板** 读取简体中文装备词缀，用 **OpenCV 模板匹配** 执行园艺台单工艺或多步骤通货流程。

> 警告：自动化可能违反《流放之路》用户协议，存在封号等风险，请自行承担。本项目仅供学习交流。

## 功能

- 解析中文客户端物品文本（稀有度、名称、词缀、数值）
- 目标规则：文本包含 + 可选数值比较（`>= > <= < =`），支持 ALL / ANY
- 工艺模式：
  - **通用**：重复点击你已在游戏内选中的工艺
  - **多步骤**：按配置右键通货、左键目标装备，并根据每步结果分支
- 多步骤流程支持：
  - 每步独立配置通货模板、动作后稀有度和词缀规则
  - 命中/未命中分别选择：下一步、重复、跳转、完成或停止
  - 可拖成循环，例如“改造命中 → 富豪检查 → 失败重铸 → 回到蜕变”
- 热键：默认 **F7** 开始、**F8** 停止；最大次数、连续解析失败、模板找不到、词缀连续无变化亦可停止
- 通货防空点：定位时通过 `Ctrl+C` 核对名称和堆叠数量，本地递减；耗尽时在点击前自动停止
- 国服客户端标价补丁：自动备份并校验基线，从 `poecurrency.top` 获取 POE1 国服行情，一键应用/恢复
- Electron + Vue 界面（花园 / 普通 / 模板 / 标价补丁）

## 启动

需要 **Node.js 18+** 与 Windows。源码首次构建标价补丁辅助组件还需要 **.NET 8 SDK**；发布后的 portable 包已内置该组件。游戏建议 **窗口 / 无边框**，不要用互斥全屏。部分环境模拟键鼠需要**以管理员身份**运行。

```powershell
cd e:\projects\poe_crafting
npm install
npm start
```

开发（Vite 热更新 + Electron）：

```powershell
npm run dev
```

`npm start` 会构建 `web/` 并用 `file://` 加载；`npm run dev` 加载 `http://127.0.0.1:5173`。

## 国服客户端标价补丁

在「标价补丁」页点一次“应用标价补丁”即可。程序会自动定位 WeGame 国服客户端，确认游戏未运行且资源文件稳定，然后：

1. 为当前客户端版本新建不可覆盖的基线目录，备份 `_.index.bin`、已有自定义 Bundle，以及中英文 `BaseItemTypes.datc64`。
2. 对清单内所有文件计算 SHA-256；任一备份损坏时拒绝继续写入或恢复。
3. 使用英文名和内部 Id 匹配行情，价格严格取接口的“最新卖1”；仅从原始基线生成 `名称 · 价格`，不会在上次价格后继续叠加。
4. 先在副本中生成并回读补丁，再通过可回滚的同盘文件事务切换到客户端；索引始终最后生效。

“取消补丁 / 恢复原版”使用同一份已校验基线。闲置自动更新约每小时检查一次；若游戏正在运行，会记录等待状态，并在游戏退出、客户端文件稳定且可独占写入后自动完成。检测到客户端版本变化时会另建新版本基线，旧备份不会被价格更新覆盖。

行情条目短暂缺失或恢复后，可在已应用状态下点“立即更新价格”重新拉取；游戏运行中会排队，退出游戏后自动写入。

## 自定义匹配图片

将 PNG 放到 `assets/templates/`，**推荐直接在 GUI 粘贴**：

1. 游戏内用 `Win+Shift+S`（或任意截图工具）截取按钮/物品槽  
2. 回到本工具窗口，在「模板配置」区选择保存目标（如 `craft_button`）  
3. 按 **Ctrl+V** 或点「从剪贴板粘贴」→「保存到模板」  
4. 右侧列表会显示是否已保存；也可用「打开模板目录」手动管理文件  

| 文件 | 说明 |
|------|------|
| `craft_button.png` | **必需** 执行工艺按钮 |
| `item_slot.png` | **必需** 目标装备本身（工艺槽或背包内，悬停后 Ctrl+C） |

多步骤模式**不需要通货图片**：通货按「非绑定 / 通用」通货页的仓库格坐标定位，右键前再悬停按 `Ctrl+C` 核对中文通货名与堆叠数量。仓库里的 `assets/templates/currency_*.png` 只供 `scripts/calibrate-stash.cjs` 标定仓库格用，不打进安装包。

截取建议：

1. 游戏 UI 缩放固定，分辨率与日常游玩一致  
2. 只截按钮核心文字/图标，不要过大背景  
3. 在 GUI 调「模板阈值」并用「测试模板匹配」验证 score  

> 规则输入框内的 Ctrl+V 仍用于粘贴文字；焦点在输入框外时 Ctrl+V 会粘贴图片。

## 使用步骤

1. 启动游戏与本工具  
2. 放入园艺台物品，截好模板并测试匹配  
3. 配置目标规则（例：包含 `最大生命`，算子 `>=`，阈值 `80`）  
4. 通用模式请先在游戏内点好要重复的工艺  
5. 点「确认并开始」，或在游戏里按 **F7**；紧急停止默认 **F8**  
6. 「刷新装备」可单次读取槽内物品；「解析当前剪贴板」可在游戏里手动 Ctrl+C 后调试解析  

## 多步骤通货流程

1. 到「多步骤」页添加、删除或排序步骤。
2. 每步从中文列表选择“使用通货”和动作前显式词缀数量，再配置动作后应有的稀有度、显式词缀数量与词缀条件；动作前条件不符时不消耗通货，动作后条件需同时满足才算命中。
3. 分别设置“命中后”和“未命中后”的去向。跳转使用稳定的步骤 ID，步骤改名或排序不会破坏跳转。
4. 到「模板」页只需保存目标装备位置 `item_slot`；通货不需要图片。
5. 直接点击「多步骤」页右上角的“开始流程”；程序会自动切换到多步骤模式。

启动后的第一个动作始终是：只将鼠标移动到目标装备上并按 `Ctrl+C`，不发送鼠标点击。读取成功后会先根据当前稀有度和词缀恢复流程状态，再使用通货。解析器兼容国服的 `稀 有 度: 魔法` 格式；真正不带稀有度但有物品等级的装备才按普通处理。高级词缀说明行、圣战者/督军标记和出售绑定信息都不会计入显式词缀数。通货不做图像识别：按窗口高度换算「非绑定 / 通用」通货页的仓库格中心坐标，命中格连同相邻格作为候选，所以不绑定固定分辨率。每个候选在右键前必须悬停并通过 `Ctrl+C` 复制出对应的中文通货名和堆叠数量。名称不符、未读到堆叠数、未复制成功或候选落在装备区域内时，都会在点击前停止。

仓库内置的 `config/workflow.json` 示例为：

1. 蜕变后检查“元素伤害提高 ≥ 19”或“最大生命 ≥ 130”；任意一条达到 T1 就保留，否则进入改造。
2. 改造反复洗，直到先得到上述任意一条 T1 目标，元素和生命两种起手完全对称。
3. 当前魔法装备恰好只有 1 条显式词缀时使用增幅石，尝试补出另一条；已有 2 条则不消耗增幅石，直接进入富豪。
4. 无论增幅是否命中都再使用富豪石；富豪后必须同时具备“T1 元素伤害”和“T1 最大生命”才完成。
5. 富豪仍未补齐则重铸为普通，并跳回第 1 步。

动作后的剪贴板读取若暂时失败，程序只会重读装备，不会重复施放当前通货。
通货首次定位或重新定位时会读取“堆叠数量”，正常循环在本地高速递减，不会每次等待剪贴板。最后 1 个可以正常用于本轮；流程再次需要该通货且找不到其他堆叠时会自动停止，不会点击空格或拿起装备。

## 配置

- `config/settings.json` — 延迟、次数、热键、窗口标题关键字、阈值等  
- `config/rules.json` — 目标规则  
- `config/workflows.json` — 多套通货流程（兼容旧的 `config/workflow.json`）

## 项目结构

```
package.json          npm start / npm run dev / npm test
electron/             主进程、IPC、热键、浮窗
  engine/             工艺引擎（正式实现）
  engine/__tests__/   vitest 单元测试与物品文本 fixture
  pricePatch/         行情、DAT 重建、基线备份、安全事务与闲置调度
web/                  Vue 界面（花园 / 普通 / 模板 / 标价补丁）
config/               settings.json / rules.json / workflows.json
assets/templates/     用户自截的匹配图 + 仓库格标定截图
assets/build/         electron-builder 的 buildResources（icon.ico）
scripts/              构建、开发热更新、仓库格标定
tools/PoeBundleTool/  独立的客户端 Bundle 读写辅助组件源码
```

## 测试

用 [vitest](https://vitest.dev/) 跑纯逻辑单元测试，Node 环境，不需要游戏窗口：

```powershell
npm test          # 单次运行
npm run test:watch
npm run typecheck # tsc --noEmit
```

覆盖 `electron/engine/` 下不依赖外部状态的部分：词缀解析与显式词缀计数、规则匹配与阈值比较、
流程状态机与配置校验、通货仓库格坐标标定、设置项 clamp、浮窗文案。
需要真实窗口、Win32 调用或截屏的代码（`vision.ts`、`win32.ts`、`input.ts`，以及
`automation.ts` 的主循环）不在测试范围内；`automation.ts` 只覆盖其中的纯判定护栏。

## 限制

- 仅简体中文物品文本
- 数值规则默认取词缀行**第一个**数字
- 多步骤模式要求目标装备可见，且仓库停在「非绑定 / 通用」通货页
- 不读内存、不注入进程
